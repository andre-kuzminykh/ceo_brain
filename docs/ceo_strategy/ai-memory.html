1. Process Goal

Assemble a unified Second Brain across funds, companies, people, meetings, threads and documents. The CEO Office manually queries every source on every context request — for meeting prep, outreach and decision-making — and pulls in the research team when deeper internal or external gathering is required.

2. Process description
CEO Office

Step 1. Classify the request

Identify entity (fund / company / person / meeting / thread / document) and request type to scope which sources need to be hit.

CEO Office

Step 2. Parallel multi-source lookup

Pull thread / template history from HubSpot, fund stage from FST / NIN / FLW, investor history from LID, upcoming and past meetings from Google Calendar / Fundraising Calendar, and document state from Data Room.

CEO Office

Step 3. Deeper external dig (when needed)

Pull LinkedIn profile and connections, plus PitchBook fund data — investments, background, exits, thesis — when the base context is not enough.

Research team

Step 4. Targeted research on demand

Escalate to research for internal (HubSpot, Telegram, Slack, Confluence) or external (LinkedIn, PitchBook, Calendar participants) gathering. Returns a research snapshot with findings, materials, links and quality tags.

CEO Office

Step 5. Manual aggregation from chats and wishlists

When history is fragmented — manually search Telegram chats and voice notes, Slack work threads and wishlist outreach logs, then interpret the scattered context by hand.

CEO Office

Step 6. Old briefs / templates lookup

Find existing one-pagers, briefs and how-tos in Confluence and hand-tag each as current, possibly outdated or needs check.

CEO Office

Step 7. Compile and produce five outputs

Build a unified knowledge context and deliver five parallel artifacts: instant brief, pre-meeting brief, document snapshot, related materials snapshot and decision snapshot.

3. Roles & responsibility
CEO Office

Owns every context request end-to-end — Artem, Alina + research team. Manually queries every source.

Research team

Pulled in on demand for deeper internal or external research; returns a research snapshot.

Source systems

Passive sources only — no automatic linking, no shared memory across systems.

4. Systems (Tools)

  • HubSpot — email, thread, template and contact history.
  • FST / NIN / FLW — fund stage trackers.
  • Investor file (LID) — investor touch history.
  • Wishlists & outreach (WSH) — outreach log.
  • Google Calendar + Fundraising Calendar — meeting history and summaries.
  • Data Room — NDA / access status.
  • Confluence — templates, briefs, how-tos.
  • PitchBook, LinkedIn — external fund and person data.
  • Telegram, Slack — manual chat search for fragmented context.

5. Artifacts

  • Instant brief — who / what happened / touch history / key facts.
  • Pre-meeting brief — fund / person / comms history / risks / theses.
  • Document context snapshot — NDA / Data Room / prior requests / access.
  • Related materials snapshot — old briefs / templates / freshness tags.
  • Decision snapshot — last touch / current stage / probable next step / warm-intro paths.
6. Metrics (Observed)
Metric Observed value
Time per brief Minutes to hours — manual aggregation across five or more sources.
Source coverage Partial and inconsistent — depends on the operator's memory of which sources to hit.
Freshness tagging Ad-hoc — no systematic current / outdated / needs check labels.
Warm-intro discovery Manual — opportunities are missed when connections are not remembered.
Context persistence None — every request is redone from scratch, no memory carried over.
7. Pain points
1. No persistent memory

Every context request is rebuilt from zero — there is no shared memory carrying prior touches, links or summaries forward.

2. Fragmented sources

HubSpot, fundraising trackers, Telegram, Slack, Confluence, Data Room — aggregating them manually is slow, error-prone and depends on who is searching.

3. Cross-entity links not formalised

Fund ↔ person ↔ meeting ↔ document connections live in operators' heads — most lookups miss links that exist between sources.

4. Material freshness not tagged

Old briefs and templates get reused without a warning — stale content reaches investors and partners.

5. Warm-intro paths missed

Likely intro paths are inferred from memory rather than data — many connection opportunities slip through silently.

1. Process Goal (TO-BE)

Deliver instant unified context via an AI Memory graph. AI Memory resolves the entity, collects from all sources in parallel, links objects into a single memory graph, infers last touch / current stage / probable next step / warm-intro paths and produces five standard briefs. The research team is pulled in only for targeted gaps or data conflicts.

2. Process description
CEO Office → AI Memory

A. Context request

CEO Office sends a single request. AI Memory resolves the entity, resolves known links and checks existing memory and related objects before fetching anything.

AI Memory

B. Parallel multi-source collection

Simultaneously pulls CRM and fund status (HubSpot, FST, NIN, FLW, LID), meetings and documents (GCL, FRK, Data Room), external context (LinkedIn, PitchBook) and internal knowledge (Confluence, Telegram, Slack, Wishlists).

AI Memory

C. Build unified memory graph

Links objects (fund ↔ company ↔ person ↔ meeting ↔ thread ↔ document), builds the memory graph, determines last touch, current stage and probable next step, and finds related NDAs / Data Room / prior requests.

AI Memory

D. Freshness and warm-intro paths

Tags materials as current / possibly outdated / needs check and computes probable warm-intro paths from the graph.

Research team · on demand

E. Targeted research on gaps only

If context is insufficient or conflicts — AI Memory issues a targeted research request (gap / goal / deadline / what to verify). Internal (HBS / TGM / SLK / CON) or external (LKD / PTB / GCL). Snapshot returns and the memory graph is updated.

AI Memory → CEO Office

F. Five standard outputs

Delivers instant brief, pre-meeting brief, document context snapshot, related materials snapshot and decision snapshot — all from one unified context.

AI Memory

G. Persist touches back into memory

New touches, summaries and links are written back into the unified memory — every request makes the graph denser and subsequent lookups faster.

7. Initiative (automation point)
Module 01

AI Memory — Unified Context Graph

A single memory graph across funds, companies, people, meetings, threads and documents — with instant briefs, last touch, probable next step and warm-intro paths on every request.

Decision quality Apr 29, 2026 № 01

What this module does

AI Memory collects and links context across funds, companies, people, meetings, threads and documents into a single memory graph. It delivers instant briefs with full touch history, related materials, current stage, last touch, probable next step and warm-intro paths. It acts as the context layer for meeting prep, outreach and decision-making.

User stories

  1. Get an instant brief on a fund, company, person, meeting or thread with full touch history — no manual hunting across mail, chats, CRM and sheets.
  2. Before a meeting, get a compact dossier on the fund and the person — comms history, prior contacts and key facts — to enter context fast.
  3. See related NDAs, Data Room and prior requests on the investor — to avoid duplicate actions and understand process context faster.
  4. The agent searches internal sources and the web for old briefs, templates and similar-fund materials and flags outdated ones — to accelerate prep.
  5. The agent shows last touch, current stage, probable next step and suggests the most likely warm-intro paths — to decide and act faster.

Delivery requirements

  • Unified memory graph across HubSpot, fundraising status files, Google Calendar, Data Room, Confluence, PitchBook, LinkedIn, Telegram and Slack.
  • Entity resolution for funds / companies / people / meetings / threads / documents with cross-source linking.
  • Freshness tagging on materials: current / possibly outdated / needs verification.
  • Five standard outputs: instant brief, pre-meeting brief, document snapshot, related materials snapshot, decision snapshot.
  • Feedback loop — every new touch or research snapshot persists into the memory graph.
