1. Process Goal

Produce every presentation material on request — one-slide fund summary, meeting pack, brief-to-slides transformation, executive pipeline slides and unified templates — by hand, pulling data from FST / FRK / FLW / LID / HBS / PitchBook / Confluence each time.

2. Process description
CEO Office

Step 1. One-slide fund summary

Pull fund status, communication history, investor history and meeting summaries; build key theses (who / where / what happened / next step / risks) and assemble a one-slide summary.

CEO Office

Step 2. Meeting pack for external meeting

Pull meeting, stage and active-stage context; in parallel collect fund data from PitchBook, comms history from HubSpot and investor history from LID; pick a template from Confluence and assemble the draft meeting pack.

CEO Office

Step 3. Briefs / tables / notes → slides

Pull fund data, status, meeting notes and a Confluence template; transform the brief / table / notes into a slide narrative and pack it into presentation format.

CEO Office

Step 4. Executive pipeline slides

Pull overall pipeline status, early and active stages, external-meeting summaries and investor touches; build an executive narrative (what changed / where is progress / blockers / decisions) and assemble the deck.

CEO Office

Step 5. Unified templates and formats

When a new deck or format update is needed — search templates, older decks and how-tos in Confluence; adapt structure and format to the current task and apply it so materials stay under a single visual standard.

3. Roles & responsibility
CEO Office

Single author of every slide artifact — collects, structures, transforms, designs and applies the template by hand.

Confluence (CON)

Template store — searched manually each time a deck is built.

Slides / Decks (SLD)

Output store — populated by hand via Google Slides / Keynote etc.

4. Systems (Tools)

  • GCL / FRK — meeting calendars and meeting-summary source.
  • FST / NIN / FLW / LID — fund and investor trackers.
  • HubSpot — communication history.
  • PitchBook — external fund data.
  • Confluence (CON) — template and old-deck library.
  • Slides / Decks (SLD) — final presentation output.

5. Artifacts

  • One-slide fund summary — status / next step / risks.
  • Meeting pack draft — context / fund / person / theses / risks / next step.
  • Brief / table / notes → slide narrative.
  • Executive pipeline deck — progress / blockers / decisions.
  • Adapted templates under a unified visual standard.

7. Pain points
1. One-slide summaries built from scratch

Every one-pager is rebuilt per fund — no reuse of the last version even when nothing meaningful has changed.

2. Meeting pack assembled across many sources

PitchBook + HubSpot + LID + FRK + FST pulled by hand for every external meeting — slow and inconsistent.

3. Brief-to-slides transformation is manual

Internal briefs and tables have to be rewritten into slide narrative — time lost on every presentation.

4. Executive pipeline deck curated manually

Every refresh requires pulling pipeline, meeting and investor context by hand — hard to keep the deck current.

5. Template consistency by memory

Without a canonical layout, decks drift visually — every author adapts the template their own way.
