1. Process Goal

Decide per context which document is needed (NDA, Data Room access, one-pager, brief, investor-facing materials), prep it from templates in Confluence, drive NDA / access / briefing workflows end-to-end and update trackers after every document action — all by hand through CEO Office.

2. Process description
CEO Office

Step 1. Pick up the request + context lookup

Read the email or meeting request, pull thread history from HubSpot, check fund stage in FST / NIN / FLW, and review prior investor requests in LID.

CEO Office

Step 2. Decide document type

Based on context — NDA / Data Room access / one-pager / brief / investor-facing material — and frame the suggested next document step.

CEO Office

Step 3. NDA workflow

Find the NDA template and checklist in Confluence, prep the draft, send for review and loop through revisions until signed.

CEO Office

Step 4. Data Room workflow

Check Data Room status — grant access, adjust, or send a reminder, then notify the investor.

CEO Office

Step 5. Document status snapshot

Keep a document status snapshot per investor: to send / sent / on revisions / signed / access granted / waiting reply.

CEO Office

Step 6. Document-process status check

Cross-check HubSpot latest thread, investor history, fund status and Data Room access to interpret the state and pick the next action — send / revise / grant / remind / wait.

CEO Office

Step 7. Briefing docs / investor-facing materials

When a meeting or materials request comes in — pull PitchBook fund data, HubSpot history and Confluence templates in parallel, then assemble a draft one-pager, brief or investor-facing pack.

CEO Office

Step 8. Post-action tracker updates

After every document action — update FST (NDA sent / waiting revisions / access granted / waiting reply), the stage tracker (NIN or FLW) and investor history in LID.

3. Roles & responsibility
CEO Office

Runs the entire document workflow — picks type, preps draft, tracks status and updates trackers by hand.

Confluence (CON)

Template and checklist library — searched manually per workflow.

Data Room (DTR)

Access control — granted and adjusted by hand.

4. Systems (Tools)

  • Email — document request, revisions, access notifications.
  • HubSpot — thread history and templates.
  • FST / NIN / FLW / LID — fund and investor trackers.
  • Data Room (DTR) — access control.
  • Confluence (CON) — NDA templates, briefs, one-pagers, how-tos.
  • PitchBook — external fund data for briefs.
  • GCL / FRK — meeting context for briefing materials.

5. Artifacts

  • NDA drafts — built from Confluence template.
  • Data Room access records — grant / adjust / remind.
  • Briefing docs / one-pager / investor-facing pack — assembled per request.
  • Document status snapshot — to send / sent / on revisions / signed / access granted / waiting.
  • Suggested next action — send / revise / grant / remind / wait.

7. Pain points
1. Doc type decided per request by hand

Every context needs a fresh human call on which document applies — slow for high-volume weeks.

2. Manual template hunt

Finding the right NDA or brief template in Confluence is an explicit search every time — time lost on every workflow.

3. Opaque document status

Status lives across email threads, Data Room and trackers — takes work to tell where an NDA or access request actually is.

4. Briefing materials assembled from scratch

Each briefing pack is rebuilt — PitchBook + HubSpot + Confluence pulled by hand, quality depends on preparation time.

5. Tracker drift after document actions

FST / NIN / FLW / LID are only updated when the person doing the action remembers to — stage data drifts from reality.

1. Process Goal (TO-BE)

Docs is a single agent that infers the document needed in each context, picks the right template, builds a checklist and drives NDA, Data Room, briefing and investor-facing workflows end-to-end — with continuous document-status visibility and auto-updated trackers.

2. Process description
Docs

A. Pick up request + context + document intent

Reads the inbound request, pulls thread from HubSpot, fund stage and investor history — and classifies the needed document (NDA / Data Room access / one-pager / brief / investor-facing). Delivers a document intent pack.

Docs

B. NDA workflow

Fetches the NDA template + checklist from Confluence, prepares the draft and handles the revisions loop — send, receive, process, update — until signed.

Docs

C. Data Room workflow

Checks Data Room status; grants / adjusts access or sends reminders, then notifies the investor.

Docs → COO

D. Document workflow snapshot

Builds and delivers a status snapshot — to send / sent / on revisions / signed / access granted / waiting — with blockers and waiting side.

Docs → COO

E. Next document action recommendation

Cross-checks HubSpot, LID, FST and DTR; interprets state and recommends the next action (send / revise / grant / remind / wait) with priority and dependency.

Docs → COO

F. Briefing docs / investor-facing pack

For upcoming meetings / material requests — pulls PitchBook + HubSpot + Confluence in parallel, assembles a draft brief / one-pager / investor-facing pack, checks completeness and fit, and delivers it with a pre-send checklist.

Docs

G. Post-action tracker updates + memory

After every document action — auto-updates FST, the stage tracker (NIN / FLW) and investor history (LID), and persists document memory, status and next expected action.

Module 07

Docs — End-to-end Document Workflows

Infers the right document, picks the template, drives NDA / Data Room / briefing workflows and tracks document status end-to-end.

Doc prep speed & quality May 20, 2026 № 07

What this module does

Docs determines which document the context requires — NDA, Data Room access, one-pager, brief or other investor-facing material. It picks the right template, builds a checklist and tracks the document workflow end-to-end, accelerating preparation, approval and dispatch without manual intervention.

User stories

  1. The agent infers from context which document is needed: NDA, Data Room access, one-pager, brief or other.
  2. Get the right NDA template and action checklist automatically — to launch the process faster.
  3. The agent drafts the next document step from the email or meeting: send NDA, respond to revisions, grant access, remind.
  4. See document status: to send / sent / under revision / signed / access granted / waiting reply — control without thread digging.
  5. The agent creates draft briefing docs, one-pagers and investor-facing materials from the current context.

Delivery requirements

  • Document intent classifier linked to fund stage and signal type.
  • Template library in Confluence with checklist and versioning.
  • NDA flow: draft → send → collect revisions → finalise → log status.
  • Data Room workflow: access request → grant / adjust → notify → monitor.
  • Briefing pack generator pulling PitchBook, HubSpot, FRK, CON into one deck / doc.
