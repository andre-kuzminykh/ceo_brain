1. Process Goal

Keep every structured register up-to-date and consistent — trackers (FST / NIN / FLW / LID), CRM, wishlists and outreach log. CEO Office prefills, syncs, deduplicates and builds wishlists by hand on every signal, meeting or status change.

2. Process description
CEO Office

Step 1. Monitor change sources

Sweep comms channels (Email / LinkedIn / WhatsApp / Telegram / Slack), calendars (GCL / FRK) and status stores (FST / NIN / FLW / LID / WSH) for anything that changes a register.

CEO Office

Step 2. Per signal: entity + record updates

Determine entity (fund / contact / meeting / outreach / investor) and build suggested record updates — which register, which fields, which values.

CEO Office

Step 3. Route to the right register

New fund / early stage → NIN; active stage / meeting / follow-up → FLW; prefill FST overall status; important investor comms → LID; meeting source → update FRK then FST / FLW.

CEO Office

Step 4. Cross-register sync

Sync FST, NIN, FLW, LID, WSH; find duplicates, missing fields and status desync; build suggested corrections and apply them by hand to the conflicting registers.

CEO Office

Step 5. Wishlist prep for a campaign

When a conference / outreach campaign is active — open / update the wishlist, pull attendees from LinkedIn, fund data from PitchBook, prior touches from HubSpot, prefill cards, apply preliminary relevance labels and flag AI / robotics investments that need manual verification.

CEO Office

Step 6. Outreach and reply logging

When outreach is sent — log to WSH. When a reply is received — update WSH and reflect the contact / history in HubSpot.

CEO Office

Step 7. Daily / weekly register health snapshot

Check completeness, pending intros, follow-up owners and campaign statuses; collect open questions and produce a register health snapshot — missing fields / duplicates / stale records / sync issues.

3. Roles & responsibility
CEO Office

Single owner of every register — prefills, routes, syncs and reconciles by hand.

Trackers (FST / NIN / FLW / LID)

Passive stores — only change when CEO Office edits them.

Wishlists / CRM / outreach

Built and logged manually per campaign and per reply event.

4. Systems (Tools)

  • Email / LinkedIn / WhatsApp / Telegram / Slack — signal sources that drive record updates.
  • GCL / FRK — meeting-sourced updates.
  • FST / NIN / FLW / LID — fund and investor registers.
  • Wishlists & outreach (WSH) — outreach and campaign log.
  • HubSpot — CRM mirror.
  • LinkedIn + PitchBook — wishlist participant and fund data.

5. Artifacts

  • Record updates per signal — register / fields / values.
  • Cross-register sync corrections — duplicates / missing fields / desync fixes.
  • Wishlist cards — contact, fund, role, relevance, prior touches.
  • Verification flags — fields that need manual review.
  • Outreach + reply log.
  • Register health snapshot — missing / duplicates / stale / sync.
6. Metrics (Observed)
MetricObserved value
Record prefillManual across five+ registers — high chance of missed fields.
Cross-register syncBy hand — desync surfaces at the weekly review.
Duplicate detectionEye-balled — duplicates live across registers until someone notices.
Wishlist buildFrom scratch per campaign — slow when participant lists are long.
Register healthSnapshot built manually — limited coverage of what is actually broken.
7. Pain points
1. Manual prefill across multiple registers

Every signal needs to be translated into the right fields across five+ registers — fields get missed regularly.

2. Cross-register sync is manual

Status desync between FST / NIN / FLW / LID / WSH only surfaces when someone runs a manual cross-check.

3. Duplicates surface late

Without automatic dedup, the same fund or contact can live in multiple registers — confusion and wasted outreach.

4. Wishlist built from scratch

Each conference wishlist is assembled manually from LinkedIn, PitchBook and HubSpot — limits how many campaigns can run.

5. Register health snapshot is lossy

A manual snapshot misses a lot — missing fields, stale records and sync issues live undetected.

1. Process Goal (TO-BE)

Tables is a single agent that auto-prefills and updates every structured register — trackers, CRM, wishlists and outreach log — syncs fields between registers, surfaces duplicates, missing fields and desync in real time, and proposes corrective updates and verification flags.

2. Process description
Tables

A. Monitor change sources + signal-to-record mapping

Monitors comms channels, calendars and status stores in parallel. For every signal, maps it to the right registry / fields / values with a confidence score.

Tables

B. Per signal: route to the right register

New fund / early stage → NIN; active stage / meeting / follow-up → FLW; overall → FST; important investor comms → LID; meeting source also updates FRK-linked fields.

Tables → COO

C. Suggested register updates

Delivers a suggested register-updates pack per signal — registry / fields / values / confidence / source — so review is a single click.

Tables → COO

D. Cross-register sync + alerts

Continuously cross-syncs FST, NIN, FLW, LID, WSH; finds duplicates, missing fields and status desync; applies fixes and emits a data sync alert with suggested corrections (or a clean signal when aligned).

Tables → COO

E. Wishlist draft pack

When a conference / outreach campaign is active — pulls attendees (LinkedIn), fund data (PitchBook) and prior touches (HubSpot) in parallel; prefills cards, applies relevance and priority labels, flags fields needing manual verification (especially AI / robotics) and delivers a wishlist draft pack.

Tables

F. Outreach + reply logging

Logs outreach events to WSH on send; on reply — updates WSH, mirrors contact and history into HubSpot, updates communication history and touchpoint log.

Tables → COO

G. Daily / weekly register health pack

Checks completeness, intros / follow-ups / campaigns; collects missing fields, duplicates, stale records and sync issues; delivers a register health pack prioritised by urgency.

3. Roles & responsibility (RACI)
CEO Office

Approves suggested updates, reviews wishlist draft packs and acts on sync alerts and register health packs.

Tables

Prefills, routes, cross-syncs, flags issues and drafts wishlists — keeps every register fresh without manual shuffling.

Registers (FST / NIN / FLW / LID / WSH / HBS)

Auto-updated stores — reflect Tables' writes with full audit trail.

4. Systems (TO-BE architecture)

  • Tables agent — signal mapping, cross-register sync, wishlist builder, health monitor.
  • Email / LinkedIn / WhatsApp / Telegram / Slack — change-source monitoring.
  • GCL / FRK — meeting-sourced updates.
  • FST / NIN / FLW / LID / WSH — auto-updated registers.
  • HubSpot — CRM mirror with contact / history sync.
  • LinkedIn + PitchBook — wishlist participant and fund data.

5. Artifacts

  • Suggested register updates — registry / fields / values / confidence / source.
  • Data sync alert — duplicates / conflicts / missing fields / suggested fixes.

Module 08

Tables — Register Sync & Wishlist Drafts

Auto-prefills trackers, CRM and wishlists; syncs fields between registers; surfaces duplicates, gaps and desync; proposes corrective updates and verification flags.

Table prep speed & quality May 22, 2026 № 08

What this module does

Tables automates filling and updating trackers, CRM, wishlists and other structured registries. It syncs fields between sources, finds duplicates, gaps and desync, and suggests what to update. It speeds up building fund and participant cards, logging outreach and keeping tables current — without manual data shuffling.

User stories

  1. The agent pre-fills tracker updates based on a signal, meeting or fund stage — no manual re-typing across files.
  2. The agent syncs fields between registers, finds duplicates, highlights gaps and desync — to keep statuses current.
  3. The agent pre-fills the wishlist with conference participants and fund cards from available sources.
  4. The agent pre-labels participant relevance and flags fields needing manual verification, especially AI / robotics investments.
  5. The agent logs outreach events and reply statuses into wishlist / CRM — to know who was contacted and who replied.

Delivery requirements

  • Signal-to-record mapping: entity, registry, fields, values, confidence score.
  • Cross-registry sync: FST / NIN / FLW / LID / WSH with duplicate and conflict detection.
  • Wishlist pipeline with participant cards, fund cards and verification flags.
  • Outreach logging across WSH and HubSpot with reply-status tracking.
  • Register health snapshot: missing fields, duplicates, stale records, sync issues.
